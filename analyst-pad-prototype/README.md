# AnalystPad — BPMN → Техническое задание

Прототип модуля для бизнес- и системных аналитиков.

## Что умеет прямо сейчас

1. **BPMN-редактор** (bpmn-js)
   - Создание пулов, задач всех типов, шлюзов, событий, связей
   - Редактирование названия и описания элемента в боковой панели
   - Сохранение / загрузка `.bpmn` XML

2. **Валидатор (строгий режим для аналитиков)**
   - Название обязательно почти у всех элементов
   - **Описание (documentation) обязательно** для:
     UserTask, ServiceTask, ScriptTask, BusinessRuleTask,
     ManualTask, SendTask, ReceiveTask, SubProcess, CallActivity
   - UserTask: предупреждение, если в описании не указана роль/исполнитель
   - ServiceTask: предупреждение, если не указана вызываемая система/сервис
   - **Связи у каждого элемента**:
     - StartEvent → обязана исходящая связь
     - EndEvent → обязана входящая связь
     - Task / SubProcess / Intermediate Event → обязательны и вход, и выход
     - BoundaryEvent → обязана исходящая связь
     - Полностью изолированный элемент → ошибка
   - Exclusive/Inclusive Gateway: каждая исходящая ветка обязана иметь название или условие
   - Проверка Start/End событий, пулов, структуры процесса
   - Минимальная длина описания ≥ 15 символов (предупреждение)

3. **Генератор ТЗ**
   - Собирает участников, задачи, шлюзы, события и поток
   - Формирует структурированное Markdown-ТЗ
   - Включает раздел с замечаниями валидации
   - Режимы: полное ТЗ / список требований / свободные заметки

4. **Блокнот**
   - Редактирование сгенерированного текста
   - Копирование и скачивание `.md`

## Как запустить

Просто откройте `index.html` в современном браузере (Chrome / Edge / Firefox).

Или поднимите локальный сервер:

```bash
cd analyst-pad-prototype
npx serve .
# или
python -m http.server 8080
```

## Публикация на GitHub Pages

Проект полностью статический (HTML/CSS/JS + CDN). Подходит для GitHub Pages без сборки.

### Быстрый способ

1. Создайте репозиторий на GitHub (например `analyst-pad`).
2. Загрузите **содержимое** папки `analyst-pad-prototype` в корень репозитория  
   (чтобы `index.html` лежал в корне, не во вложенной папке).
3. Settings → **Pages** → Source: **Deploy from a branch**  
   - Branch: `main` (или `master`)  
   - Folder: `/ (root)`  
4. Save. Через 1–2 минуты сайт будет доступен:

```
https://<ваш-логин>.github.io/analyst-pad/
```

### Через Git (терминал)

```bash
cd analyst-pad-prototype
git init
git add .
git commit -m "AnalystPad: BPMN → ТЗ"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/analyst-pad.git
git push -u origin main
```

Затем включите Pages, как в шаге 3 выше.

### Важно

- Файл `.nojekyll` уже есть — GitHub не будет обрабатывать сайт через Jekyll.
- Все пути относительные (`css/`, `js/`) — работают и в корне, и в подпапке репозитория.
- bpmn-js подключается с CDN (unpkg) — интернет на стороне пользователя нужен.

## Как пользоваться

1. Нарисуйте процесс в BPMN-редакторе (добавьте пулы, задачи, шлюзы).
2. Выделите элемент → заполните **Название** и **Описание** в правой панели.
3. Нажмите **Проверить схему** — увидите ошибки.
4. Нажмите **Сгенерировать ТЗ** — документ появится во вкладке «Блокнот».
5. Отредактируйте текст и скачайте `.md`.
